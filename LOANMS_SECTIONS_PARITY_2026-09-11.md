Environment for this pass: frontend only (Node/npm available; **no `dotnet` binary, no live PostgreSQL, no headless browser** — network egress is restricted to npm/PyPI/crates/GitHub domains, so `dotnet restore`/NuGet, a running API+DB, and an actual rendered-browser screenshot diff were **not possible here**). **Bugs found and fixed (`LoanApplicantTabs.tsx` Employment tab, `LoanDetailPage.tsx` Bank Details table):**
1. **Insurance loans showed the wrong Employment tab entirely.** React was rendering the salaried base grid (Employment Type / Net Monthly Salary / Company Name / Designation / Company Type / Official Email ID / Office Address / Office PIN Code) *plus* an Insurance/Nominee block underneath, for every loan type. Vanilla (`efin-app.js:2599-2615`) replaces the whole grid for `loanType==='insurance'` with **only**: Proposer Income Type, Annual Income, Insurance Type, Sum Assured, Policy Term, Payment Frequency, Est. Annual Premium, Preferred Insurer, Existing Policy (+ conditional Existing Coverage), Nominee Name, Nominee Relationship, Nominee DOB — no Company/Designation/Office fields at all. Fixed: added a `loan.loanType === 'insurance'` branch that renders exactly this set with Vanilla's labels/values.
2. **"🏢 Business Details" group didn't exist in Vanilla** — the wizard captures `bizVintage/bizTurnover/bizNetProfit/bizGst/bizItrFiled/bizType`, but the Vanilla Loan-Detail Employment `fieldGrid` (`efin-app.js:2659-2665`) never includes them (only `_empBaseFields + _propFields + _coAppFields + _carFields + _eduFields`). Removed the group.
3. **"Property Details" had an extra "Property Address" row** not present in Vanilla's `_propFields` (6 fields: Type/Value/Builder/City/Ownership/Under-Construction). Removed.
4. **"Co-Applicant" had two extra rows** ("Relationship", "Email") not in Vanilla's `_coAppFields` (Name/PAN/Aadhaar/Mobile only), and used bare labels ("Name","PAN") instead of Vanilla's "Co-Applicant Name"/"Co-Applicant PAN"/etc. Fixed to the 4 Vanilla fields/labels.
5. **"Vehicle Details" had a duplicate price row** ("Price" + "Ex-Showroom") where Vanilla has one field, "Ex-Showroom Price" (`app.carPrice`), plus wrong order/labels ("Mfg Year" vs "Manufacture Year", "Dealer" vs "Dealer Name"). Fixed to Vanilla's order/labels/single price field (falls back to the wizard's `vehiclePrice` when `vehicleExShowroom` is empty, e.g. used-car flow, so no data is dropped).
6. **"Monthly Obligations" was shown on the Employment tab** — Vanilla captures obligations but never displays it on this tab (it's surfaced elsewhere, out of this scope). Removed from the base grid.
7. **Lender Details → Bank Details table always showed the "Application Number" column.** Vanilla (`index.html:1174`, `bank-col-appno`) hides this column specifically for `role==='partner'`; Partners should only see Temp Application Number. React rendered it unconditionally for every role. Fixed: column (header + edit/view cells + empty-state colSpan) is now suppressed when `user.role === 'Partner'`.

All fixes are presentation-layer only inside the existing components (no new components, no schema/API changes, no business-rule changes). `tsc -b`, `vitest run` (178/178), and `vite build` all pass after the fixes.
